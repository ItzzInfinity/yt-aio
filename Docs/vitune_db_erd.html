Song is the hub 3 junctions Android Room

The shape of it

ViTune is an Android Room database, so every table is a Kotlin entity and every relationship is a declared foreign key. Song is the hub and its primary key is the YouTube video id, which is why a ViTune backup can be merged with anything else keyed the same way. Three junction tables carry the many-to-many relationships to artists, albums and playlists; three more tables hang one-to-one or one-to-many detail off a song. Everything else is app state rather than music.

Relationships

Every one of these is a real foreign key in the file, not an inferred one. The path is what a query has to walk to answer the question in the title.

Song ↔ Artist
many-to-many
Song.id → SongArtistMap.songId ←→ SongArtistMap.artistId → Artist.id

An artist name is not stored on the song. Reaching it always costs a join, and a song with three credits has three rows here. SongArtistMap has no position column, so the order the app credits artists in is not recorded.

Song ↔ Album
many-to-many, one in practice
Song.id → SongAlbumMap.songId ←→ SongAlbumMap.albumId → Album.id

position holds the track number. The junction allows several albums per song, which is what makes compilations expressible.

Song ↔ Playlist
many-to-many
Song.id → SongPlaylistMap.songId ←→ SongPlaylistMap.playlistId → Playlist.id

position is the running order. The SortedSongPlaylistMap view is this table ordered by position, so the app can read a playlist in order without an ORDER BY.

Song → Format
one-to-one
Format.songId → Song.id, with songId as the primary key

One cached stream per song: itag, mime type, bitrate, content length and loudness. The primary key on songId is what makes it one-to-one rather than one-to-many.

Song → Lyrics
one-to-one
Lyrics.songId → Song.id, with songId as the primary key

fixed is plain text, synced carries timings, startTime offsets them.

Song → Event
one-to-many
Event.songId → Song.id

One row per play with a timestamp and playTime. Counting rows per songId gives a play count; Song.totalPlayTimeMs is the same information already summed.
